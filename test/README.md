# 核心流程测试

保留 9 个流程测试，媒体组形状和故障种类参数化后共 15 个场景。使用真实 SQLite、Pillow、
ffprobe 和 ffmpeg；Telegram 与 tdl 网络调用使用注入的桩，发送参数仍受实际 Client 签名约束。

| 测试文件 | 保护的行为 |
| --- | --- |
| `test_archive_workflows.py` | 原始文件身份、双层去重、图片转换、视频元数据与缩略图、媒体组与拆组、上传回退、失败结算、临时文件清理、checkpoint 重试/跳过/恢复、链接入口与真实来源分离 |
| `test_storage_workflows.py` | 已有数据迁移与搜索、归档原子写、删除与重试回退的原子性、共享文件保留、tdl 部分成功与下载回退 |
| `test_control_workflows.py` | bot 鉴权、发起人绑定与防重放、确认范围、等待扫描后的状态复核、启动装配、无副作用导入、可恢复备份与失败间隔 |

删除单独的格式化排列、空输入排列、值对象字段、私有辅助函数和重复回归用例。
关键历史问题合并进流程断言，例如路径穿越、转换前哈希、下载大小不符、短组上传响应、入口身份错位及确认期间状态漂移。
上传目标与实际返回的消息 id、扫描器识别链接、确认删除后的回退也由流程断言保护。
可选压缩、回填脚本和界面文案不再拥有独立测试矩阵；后续改动这些功能时补充相关流程验证。

新增测试应优先扩展相应流程，断言归档内容、数据库状态、checkpoint 和恢复结果。
镜像的递归模块检查、运维脚本导入与 libx264 冒烟继续在 CI 和发布流程中执行。
